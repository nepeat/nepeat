Candidate: `https://github.com/dentproject/dentOS/tree/8a74afad.../accton/arm64/as4224/as4224-52p` (same pattern for all; build.py:179 builds it as `<repo>/tree/<commit>/<pdir>` with pdir relative to `packages/platforms`). Fix: `.../tree/<commit>/packages/platforms/<pdir>` (the Stratum URLs are correct). The 4610 dual-arch sources point to the armel dir only; fine, but say so or point at the yml permalink.
M2. DENT `license` text is not supported by the captured evidence. Candidate says "Eclipse Public License 1.0 / Apache-2.0 (ONL-derived)". The only licence evidence captured is the dentOS LICENSE first lines in the manifest ("As ONL is based on Debian; the following licenses are imported: ... https://www.debian.org/legal/licenses/"); no LICENSE file is in the raw capture, the captured yml/py files carry no licence header, and "Apache-2.0" for DENT appears nowhere. This is the same class of defect as nos-review M1 (ONL). Either capture the upstream LICENSE (cannot offline) or reword to what was observed, e.g. "dentOS LICENSE (ONL-derived; opens with Debian/third-party licence notes) - not independently resolved to one SPDX id; upstream rights; factual extraction". Stratum "Apache-2.0" is supported (LICENSE head "Apache License Version 2.0" in manifest), but that LICENSE file is also not in raw: note only.

### Should-fix

Placeholder not flagged in data. `"asdf"` / `"asdf leaf 2"` / `"Stratum device device:s204"` are printed correctly but only the handoff says they are placeholders; the source `coverage` just says names are "as printed upstream".
