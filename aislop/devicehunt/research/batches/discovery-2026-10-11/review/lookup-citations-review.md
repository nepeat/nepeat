## Should-fix
1. **The path alternative of the rule is not as conservative as claimed.** `_LOCATOR` accepts any `[A-Za-z_][^():;]*/[^():;]+` followed by `:N`, so anything with a slash and a trailing `:digits` is stripped: spaces and no extension required. Tested strings stripped: `x (Rack A/B:3)`, `x (CPU/PCH:1)`, `x (TX/RX:1,2)`, `x (RJ45/SFP:1-4)`, `x (e1/1:2)`, `Ethernet0 (Eth1/1:4)`, `x (Slot A/B:2)`; the bare trailing alternative strips `port Eth1/1:4`, `speed 10G/25G:2`, `ratio 1/2:3`. Switch breakout names like `Ethernet1/1:4` are plausible in this dataset class. Kept (correct): `D52B-1U (C621)`, `FB_temp(0x4C)`, `(8086:1521)`, `Ethernet0 (1,2,3,4)`, `Eth (1:2, 3:4)`, `x (SPEC: "a/b:3")`, `(page 3)`, `(Fig. 2:3)`, `(INSTALL:2)`, `x (see foo.txt:3)`. Real-data impact today: none. I enumerated all 7,378 stripped groups by shape (4,058 `file.ext:N`, 732+571+295+621 slash paths with extensions or known dirs, 690 `L<n>`, 120 `file:N-N`, 49 `line N`, multi-locator groups) plus a 40-item random sample: every one is a genuine path/line locator; 0 trailing-bare strips; 471 slash groups without an extension are DMI model dirs (`Desktop/Inspur/NF5270/NF5270M3/<MAC>:39`) and ONIE `rootconf/sysroot-lib-onie/gen-config-platform:N`, all real. Effect of a future false strip is only relabelling a value match as "cited-path only" (rows are unaffected), but "no real values stripped" is true of the current data, not of the rule. Suggested tightening: require the last path segment to contain a letter-extension `\.[A-Za-z]\w*`, or the DMI/`src/`-style shape (a hex/MAC-like last segment), and drop the bare-trailing alternative for slash-only forms (it has no instances anyway).
2. **`fact_names` / `fact_name_count` semantics changed and the user-facing scope text does not say so.** Before, they listed every fact name whose value contained the query; now they list only value-proper matches (NF5280M6: `facts[19]` -> `facts[7]` + `cited-path only: 12 facts`; `fani.c`: 76/88 rows' `matched_in` changed; `json:4`: all 47 rows now `facts_citation_only` only). The catalog `scope` still reads "matched_in names where the query was found (identity fields and/or fact names, not values)" with no mention of `cited-path only` or that citation-only names moved. Add one sentence to the scope string (JSON consumers read `scope`), e.g. "Fact names whose only hit is inside a source citation (path:line) are listed under cited-path only / matched_in_detail.facts_citation_only, not facts[]." Also `cited-path only: N facts` counts distinct fact NAMES, not facts; consider "N fact names".
