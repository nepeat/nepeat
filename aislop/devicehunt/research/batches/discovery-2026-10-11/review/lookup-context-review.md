## Should-fix

   - contain "software" (OK): Meta OpenBMC platform (19), ONIE machine (61), ONL platform (91), SONiC platform (63), OpenBMC entity-manager config (183), community dtb gist (1, "networking software artifact reference").
   - **do NOT contain "software"**: `OpenBMC machine` / "BMC firmware machine definition" (14) and `Linux BMC device tree` / "BMC device tree source" (12). 26 rows total.
   - Evidence it matters: `lookup NF5280M7` returns the OpenBMC machine row `nf5280m7` with `matched_in = identity; facts[12]: obmc_comment_lines, obmc_commented_out_lines, obmc_conf_path, ...`; the row's kind has no "software", so a reader applying the stated rule would not treat it as software-reference. (Not new-discovery-specific; the "new discovery brands" are exactly these OpenBMC/Linux-DT ones.) Suggest wording by brand/source rather than kind, e.g. "Software/firmware-reference identities (OpenBMC, ONIE, ONL, SONiC, Linux device-tree files)...", or normalise those two kinds to include "(software reference)" in the importers. Non-software kinds containing "Machine" (Oracle Database/Exalogic Machine) are hardware and correctly out of scope.
   - Code is kind-agnostic so `matched_in` itself is not affected; only the explanatory sentence.
