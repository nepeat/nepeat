## Verdict: ACCEPT with notes

No capture or fact problem. One must-fix is a modelling problem, not an evidence problem: the model-field choice is not safe for Oracle. Using Red Hat's short `model` field for Oracle (a) throws away 28 correct exact merges, (b) creates 25 near-duplicate devices beside existing `Sun Fire X...` / `Oracle Server X...` identities, and (c) collapses distinct products into one device (`Oracle X3-2` holds both `Sun Server X3-2` and `SUN Netra X3-2`). The fix is a rebuild of the candidate for the 42 Oracle records only. Everything else can be imported as is.

## Must-fix

**M1. Oracle: use the full printed product name as the model, not the `model` field.** Evidence, all from the candidate vs the current catalog:
- Oracle `make` is part of the product name, not a company label. Red Hat splits the name inconsistently: `Sun Fire X4170` is make `Sun Fire` + model `X4170`; `SUN Netra X3-2` is make `SUN` + model `Netra X3-2` in one listing (id with the merge) and make `SUN Netra` + model `X3-2` in another (4651); `SUN Blade X6270 M3` is make `SUN` + model `Blade X6270 M3` (3107) but make `SUN Blade` + model `X6270 M3` (4711); `SUN X3-2B` is a third spelling of the same Blade; `Oracle Database Appliance(ODA)` becomes `Database Appliance(ODA)`.

**S1. Quanta model field is inconsistent, and not in the same convention as the pending ubuntu-cert candidate.** Seen in the candidate: make `QuantaGrid` + model `D51B-1U` (family dropped) next to make `Quanta` + model `QuantaGrid S74G-2U`, `QuantaGrid D51PS-1U`, `QuantaPlex S24P-5U`, `QuantaMicro X10E-9N` (family kept), make `QuantaGrid` + model `QuantaGrid D55Q-2U` / `D44N-1U` / `QuantaEdge EGX88D-1U` (Red Hat itself prints the family twice). 13 of 83 models keep a family prefix; the rest drop it. Related split annotations stay in the model: `D52B-1U (C621)`, `D52B-1U(C624)`, `D52BQ-2U 3UPI`. Cross-source effect: the pending ubuntu-cert candidate uses `QuantaGrid D52BQ-2U` style names under the same `Quanta` brand; only 10 of 81 Red Hat Quanta models equal an ubuntu model string, whereas family-prefixed names (make-dedupe) would match 28. The model field does give 3 exact merges into existing `Quanta` devices (`D53XQ-2U`, `T41S-2U` x2 listings), which use the bare form. The coordinator should pick one Quanta rule for both candidates before either is integrated; either is defensible (the existing `Quanta` brand uses bare codes, the existing `QCT` brand and ubuntu use family names). If left unchanged, 18 ubuntu/Red Hat Quanta pairs will remain duplicate devices. Not a blocker.

**S2. Wiwynn short models lose family context.** `ASPEN 2112T` becomes `2112T` and `CLOUD SERVER 5U10B` becomes `5U10B`; both are bare short codes that look like part numbers. The other 12 Wiwynn records are fine (`SV7220G3 SV7220G3-S` becomes `SV7220G3-S`, a faithful base model). Suggest keeping the full printed name for those two, or accept and note.

**S3. Inspur model with a leftover brand.** Id 142207: make `Yingxin`, model `Inspur NS5480M6`, product printed `Yingxin Inspur NS5480M6`. The model field itself contains `Inspur `. It will not merge with `NS5480M6` of the IEIT records in the same file. Strip or add to the handoff list as an as-printed oddity.

**S4. Titles repeat the brand.** Title is always `<brand> <product name>`, so 61 titles read `Quanta Quanta S210-X22RQ` (28), `Inspur Inspur NF...` (18), `Oracle Oracle Server X5-2` (8), `Celestica Celestica S2121` (7). The existing catalog has the same defect (`Oracle Oracle Server X5-2`-style titles from earlier imports), and titles only matter for newly created devices, so this is cosmetic. Suggest title = `<brand> <model>` (the sonic template). After M1 the Oracle titles become `Oracle Sun Fire X4170` etc.

**S5. Template text left in 183 listing-only coverage strings.** They read "no detail page captured (request cap) (or captured but unusable, see note)". The parenthesis belongs only to `5864`. Drop it from the 182 others.

**S6. Null prints as `None`.** One cert row in id 3269 has `publishedOn` null; the fact value is `20659|Red Hat Enterprise Linux|7.0-7.x|x86_64|None|Certified`. Source is null, not the string `None`. Suggest `-` or `(not printed)`; minor.
