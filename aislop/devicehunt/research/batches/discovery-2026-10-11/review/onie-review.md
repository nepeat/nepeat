## Findings
- S1 (should-fix, label): `onie_install_cpu_lines` is not CPU-only. For 7 quanta dirs it holds INSTALL:1 "Add support for QuantaMesh ... board", the INSTALL:4 title, the "Installing ONIE on ..." line and e.g. INSTALL:131 "2. Power on the Quanta Rangeley CPU board Switch" (matched on the word CPU/board), and for the 5 ingrasys dirs it only duplicates `onie_install_heading_lines` (e.g. ingrasys_s8900_54xc INSTALL:2 appears under both). Values are literal and cited, so no evidence error, but the name overclaims; rename (`onie_install_board_lines`) or restrict to lines that print a CPU name, and drop exact duplicates of the heading fact.
- S2 (should-fix, "as printed" fidelity): two normalisations in values labelled literal. (a) `onie_install_build_machine_arg` collapses the double space in INSTALL:11 (`MACHINEROOT=../machine/alphanetworks  MACHINE=...` printed with two spaces; also truncates the surrounding text) in 59 devices; (b) `onie_install_supported_platform_lines` writes `T5032-LY6 [cpu module]` where the file prints ` - T5032-LY6  (cpu module)` (24 lines, 3 quanta dirs). Harmless but contradicts the "exact strings as printed" rule; either print verbatim or call the facts normalised in the handoff.
- N1 (note): `onie_vendor_dir_as_printed` and `onie_machine_dir_as_printed` come from the tree path (and the repo URL), not from a printed line; there is no file:line. Fine as directory-name labels, "as printed" is slightly loose. `onie_repo_commit` likewise has no file:line.
- N2 (note): `ONIE_ARCH ?=` (default-assignment, e.g. inventec_d7054q28b machine.make:4) and the other assignments are overridable by make command-line args (the READMEs show `VENDOR_REV=0/1` builds). The facts say "literal assignment" which is accurate; they are not installed-device facts, and the coverage text already says so.
- N3 (note): `onie_machine_rev` has several values for 8+ devices (ifeq branches), all kept and flagged; readers should not treat the first as the value. `alphanetworks_snh60a0_320f` and `..._320fv2` share a README model label (preserved).
- N4 (note): the raw captured files (not the candidate) still contain person names/emails in machine.make comments (5 quanta files). That is upstream text kept immutably in data/raw, in line with the policy that raw data may contain contact info; the candidate carries none. Don't publish data/raw.
- N5 (note): the handoff's "Decisions needed" item (feeding the overlap-dir INSTALL/CONSOLE_SPEED/etc. facts into the existing `onie` source) is a coordinator decision, not part of this candidate; it would require a change to the existing source's import so it should not be done piecemeal.
