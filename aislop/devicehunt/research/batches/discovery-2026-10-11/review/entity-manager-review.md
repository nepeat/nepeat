## Findings

### Must-fix
M1. Inspur wording in the candidate. `em_selection_rule` on the three ieisystem identities reads `dir:ieisystem (related to target Inspur; relation is coordinator context, not evidence) (...)` (candidate lines 1714, 1763, 1816). Although disclaimed, it puts "Inspur" in catalog facts and in the search index: FTS `match 'Inspur'` returns exactly these 3 entity-manager devices (verified in the scratch copy). The coordinator decision was that the relation is context only. Reword to what the file establishes, e.g. `dir:ieisystem (selected by directory name on coordinator request; no vendor string match)`, and keep the Inspur/IEIT sentence in the handoff only. Handoff line repeating the label should change to match.
M2. Fabricated token `bus None`. `em_exposes_psu_entries` for `Ventura2 SCM` and `Ventura2 SCM 2700` prints `Artesyn7000552480000PowerSupplyUnit: PSU_1_1 [bus None addr 0x90] (L190)` (25 entries each, 50 entries incl. `PowerShelf: PSU_SHELF_1 [bus None addr 0x20] (L862)`). The entries have no `Bus` key (e.g. ventura2_scm.json:190-200 has `Address "0x90"`, `Name`, `Type`; shelves have `SerialPort "ttyRS485-1"`). "None" is a Python artifact and reads as a value; silence is not a value. Omit the bus clause when the key is absent (or print `no Bus key`; optionally `serial ttyRS485-1`). Regenerate.

### Should-fix
S1. Handoff claim "every hit is a `BOARD_MANUFACTURER`/`PRODUCT_MANUFACTURER` value inside a Probe" is false for 3 hits: minerva_cmm_misc_boards.json:87 (`"Manufacturer": "Quanta"`), :102 and :117 (`"Manufacturer": "Celestica LLC"`) are literal `Decorator.Asset` values in three objects whose Probe is a DevicePresence match. Those three objects are in the candidate because of that, and the 2 celestica hits come only from them. Correct the handoff and mention that these are the only literal asset blocks.
S2. `em_asset_*` facts mix FRU-field references with literals under the same keys and without a label. 169 `$BOARD_MANUFACTURER`, 169 `$BOARD_PRODUCT_NAME`, 168 `$BOARD_PART_NUMBER`, 3 `$PRODUCT_*`, 1 `$CHASSIS_PART_NUMBER` are references; but `Quanta`, `Celestica LLC`, `AMD`, `AMD EPYC Venice SP7`, `MINERVA_T21_GENOA`, `Minerva Janga SMB`, `Minerva Tahan SMB` are literals and `NOT_SUPPORTED` is a placeholder. The handoff says 179 are references; that is only true of most. A buyer reading `em_asset_model: $BOARD_PRODUCT_NAME` cannot tell it is a placeholder. Cheap fix: print references as `FRU-field reference $BOARD_PRODUCT_NAME (not a literal value)` and literals as `literal "Minerva Janga SMB"`; put one sentence in the source coverage text. Also state that `NOT_SUPPORTED` is the file's placeholder.
S3. Useless identities for 3 objects. `$Name [minerva_cmm_misc_boards]`, `...#7`, `...#8` are template-name models; the file's literal `Model` strings (`MINERVA_T21_GENOA`, `Minerva Janga SMB`, `Minerva Tahan SMB`) are far more useful but only in facts. Cheap improvement: model suffix with the literal Asset Model (e.g. `$Name [minerva_cmm_misc_boards: Minerva Janga SMB]`) or accept as is and document. Same minor issue for 22 other models containing `$` template tokens (`Clemente HDD Carrier $bus - 25 % 11`, `Yosemite 4 Fan Board $bus % 30 [...]`): they are literal Names, but add one coverage sentence that `$` tokens are template variables as printed.
S4. Handoff text errors (no data impact): FP5280G3 fan board has 12 `I2CFan` on bus 8 at two addresses (0x22 for fan0-2, 0x20 for fan3-5), not all 0x22 (candidate itself is right: fp5280g3_fanboard.json:8 to 327). Non-strict JSON files among the selected: 9, not 12. Names colliding among imported: 41, not 42 (42 includes excluded `SanMiguel $Name`). "PSU driver names are scarce in the selected scope" is wrong: Ventura2 SCM / SCM 2700 `em_exposes_types` list Artesyn7000552480000PowerSupplyUnit (24), DeltaECD17020037PowerSupplyUnit (24), Delta/Panasonic BBU, capacitor-bank, power-shelf and monitor-module types, i.e. exact PSU/BBU type strings; only the 25-entry `em_exposes_psu_entries` list is capped.
S5. `1 entries` grammar in `em_exposes_count` ("1 entries", NFC Adaptor, BMC Storage Module): cosmetic, fix with `entry`.
S6. Selection not auditable outside the captured set. Add to the handoff or `selection-table.json` the path list of the 192 unselected JSON files (e.g. `git ls-tree` output saved before the clone was deleted) so a reviewer can confirm no in-scope file was skipped; currently the unselected-set claims (zero string hits outside the 169, nothing missed) are unverifiable.
