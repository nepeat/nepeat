## Identity convention
- **Module types (11): brand `Unattributed accessory`** (review S1; the printed PSU/fan code precedent), affiliation still `[Edgecore, listing_holder]` so the Edge-Core `all` inventory sees them; `FAN-1U-1x1I-F/-B` merge with existing rows by exact string, `YM-2651Y B01R/C01R` (space) stay separate from `YM-2651Y, B01R/C01R` (comma; lead only).
- Device-type brand = canonical target name when the YAML `manufacturer` is a reviewed TARGETS alias: `Edgecore` -> **Edge-Core** (19 + 11), `Inspur` -> **Inspur** (2); else as printed (`QCT`). model = YAML `model` exactly (module `YM-2651Y B01R` keeps its space). The printed manufacturer is kept as fact `netbox_manufacturer_as_printed`.
- source id `netbox-dt-<mfr-slug>-<model-slug>` (device types) and `netbox-mt-...` (module types; prefix differs from the assignment only to avoid cross-kind collisions). **kind** now describes hardware, reusing existing catalog vocabulary: Edgecore device types `switch` (Edge-Core has 85 `switch` rows; the YAMLs only state ethernet interfaces, console and PSU/fan bays, which makes switch unambiguous for these files), Inspur `server` (existing 18 `server`; YAML has BMC/PSU/PCIe bays and a rack_servers spec URL), QCT `server platform` (existing family kind), module types `Power Supply FRU` / `Fan Module FRU` (existing kinds; YAML description/profile/power-ports state PSU or fan). Kind is dropped on merge.
- identifiers: `netbox_device_type` (`netbox_module_type` for modules) = model, and `part_number` where the YAML has one.
- **Tier `community`**: existing tier, already used for devicecode, the PCI-ID repository and the AS7772 DTB gist (public, contributor-maintained, no vendor attestation); it fits better than `project` (software-platform definitions) or `vendor`.
- **Affiliation** one per record: `[manufacturer as printed, listing_holder]`. `listing_holder` is the existing non-manufacturer role already used for UL and the Ubuntu cert listings (682 rows) for a third-party catalog entry that names a company; it makes the record visible to target lookups without any manufacturer claim. Not used: manufacturer/registry_manufacturer/declared_*; `documentation_vendor`/`platform_vendor` would imply the company wrote the document or software.
- Coverage (every source): community-maintained device-type library for NetBox; values may be datasheet-derived but are not vendor statements; power draw values are library entries, not measurements; manufacturer string is a label, not a manufacturer/ODM/deployment/support claim; absent keys are omitted.
