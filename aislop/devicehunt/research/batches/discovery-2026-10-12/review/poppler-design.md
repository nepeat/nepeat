utility contract:

- accept an existing local PDF, an explicit NEW output path and explicit Poppler tool directory; never invoke a shell, fetch, install, import, alter a manifest or overwrite existing captures. keep the absolute Nix path in the caller's invocation, not a hardcoded runtime requirement. hash the PDF before extraction and verify it is unchanged afterward.
- run `pdfinfo` under a fixed locale, validate its successful exit and a positive integer page count; reject encrypted/password inputs for this bounded feature. retain tool/version information and stderr/warnings as provenance. validate the PDF header. set finite subprocess timeouts; on failure publish no accepted sidecar.
- extract **each ordinal 1…N separately** with an argument list equivalent to `pdftotext -f n -l n -layout -enc UTF-8 -eol unix -remove-hyphens none -nopgbrk <pdf> -`. per-page calls avoid guessing page boundaries from form feeds; preserve every blank page, whitespace and suffix character. do not strip/filter pages, normalize identifiers, OCR, infer table structure or merge columns. explicitly disabling hyphen removal matters because this installed version's help says the default is `all`.
- serialize `pdf_sha256`, a stable honest method label such as **Poppler pdftotext -layout embedded text; no OCR**, the actual pdftotext/pdfinfo versions, explicit encoding/EOL/layout/hyphen/page-selection parameters, positive `pdf_page_count`, and exactly N sequential `{page: int, text: str}` entries. versions need to agree for the supplied tool pair; record extraction UTC time and source filename as provenance. producer code/tool paths or executable hashes are useful optional reproducibility fields, not authority to change source roles. publish only after all calls and final hash/count validation succeed; retain stderr without pretending a warning-free or visual-reviewed result.

minimal validator/import changes:

- introduce a shared validated capture helper returning pages plus extraction metadata; keep `read_pages(body, pdf_sha256)` returning its current page list for the many existing callers. allow exactly the existing **pypdf embedded text; no OCR** label and the new Poppler label. legacy sidecars remain valid unchanged; unknown/OCR labels remain rejected.
- for Poppler require the version/parameter metadata and `pdf_page_count == len(pages)`; reject booleans as counts/ordinals, malformed root/page objects, reordered/missing/duplicate pages, bad hash and non-string text. validation is offline and must not execute installed tools during import/rebuild.
- `documents.import_bundle` and `reference_documents.prepare/import_bundle` currently hardcode the pypdf label in `documents.extraction_method`. propagate the validated method instead. preserve `prepare`'s public `(path, [(entry,pages),…])` shape by using a prepared entry copy with the method overwritten from validated sidecar metadata; never trust a manifest-supplied method field.
- retain `dependency`'s sibling filename, resolved-parent and SHA checks, %PDF check, reference HTTPS/tier/unique metadata checks, bundle page counts, all linked FCC documents and complete-reference-collection validation before replacement. existing `prepare` validates the supplied collection, while replacing a partial reference collection intentionally removes old sources: the integrator must still supply the **complete existing collection plus additions**, never just the five PSU PDFs.
- no schema migration: the extraction-method column is already TEXT. mixed legacy pypdf and new Poppler captures can coexist; don't relabel old captures or re-extract them just to homogenize the bundle.

meaningful tests: validate old and new sidecars; reject missing/false method metadata, hash/version/options/count failures, boolean/nonsequential pages and OCR; preserve blank pages; confirm each importer persists the true method and a corrupt final dependency leaves the old snapshot unchanged. test the utility's subprocess argument construction, empty-page retention, source change, failed/time-out page, mismatched tool versions and refusal to overwrite using injected/mocked subprocess results. no tool invocation in the default guarded offline suite. a separate bounded manual extraction of a known real saved PDF can check actual tool behavior in an assigned staging path, outside tests. run focused tests first and the required full suite before any later combined code/data promotion.

limits: a correct complete extraction is still discovery text, not visual evidence. Poppler layout can reorder text, misalign tables and drop image-only content; retain numerical/curve/region/model visual QA from the PSU review. pdfinfo-derived completeness and a trusted generator prevent accidental omissions but do not cryptographically prove a claimed tool execution; capture hashes and review remain essential. `read_pages` is used by lineage and several source parsers, so legacy compatibility and fail-closed method validation matter. no broad archive/recipe redesign is necessary for this milestone; register later prepared artifacts through the existing reviewed integration path.
