## Netlist format (`*.net.json`)

    {format: "i2cfpga-netlist-1", source, fabric, notes, note_examples,
     cells: [{name, kind: site|tile, type, tile, implicit, pins: {pin: net},
              unknown_pins: [...], fasm: [raw FASM lines]}],
     nets:  [{name, driver: [cell, pin] | ["$VCC"/"$GND", ...] | null,
              const, sinks: [[cell, pin], ...], fasm: [raw lines], ppips: [...]}],
     unassigned: [[raw line, reason]]}

- Cell names are the global site names (`SLICE_X10Y85`, `RAMB18_X0Y44`,
  `IOB_X0Y100`, `PCIE_X0Y0`, ...). Tile-level configuration that belongs to
  no single site is a pseudo-cell `TILE:<tile>` (here: BRAM tiles, holding
  `RAMB36.*`, `ZALMOST_*_OFFSET`, `CASCOUT_*`).
- Net names are `<driver site>/<pin>` (`SLICE_X0Y102/AQ`), `$VCC/<TIEOFF>`,
  `$GND/<TIEOFF>`, or `$VCC_DEFAULT` (the INT IMUX/BYP/FAN default tie).
- `fasm` holds the raw FASM text of each line the object owns. The inverse
  writes these lines and runs prjxray-style `merge_and_sort`, so it is exact
  by construction; `check` proves the partition (each input line owned once,
  nothing extra) and the text equality.
- `ppips` lists the pseudo pips a net uses (`TILE.DST.SRC always|default`).
  They have no configuration bits and are derived information.

## Method

1. **Classify each FASM line** (`Builder.classify`):
   - *pip*: `TILE.A.B` where the tile type has a pip `B -> A` (or a
     bidirectional pip between A and B) with segbits. Tile types that use
     another type's segbits through a tilegrid `alias` (the `*_SING` IO tiles,
     `HCLK_*_BOT_UTURN`) are handled.
   - *site*: the second name component names a site. Rules: `SLICEL_X0` /
     `SLICEM_X1` by relative X; `BUFGCTRL.BUFGCTRL_X0Y5`, `BUFHCE.BUFHCE_X1Y8`
     by relative name; `RAMB36`, `MMCME2_ADV`, `GTPE2_*`, `PCIE` by prefix;
     `<PREFIX>_Y<n>` by relative Y, **except IOB/ILOGIC/OLOGIC/IDELAY in a
     2-site tile, where `_Y0` is the upper site** (global Y even). This is
     the rule fasm2bels uses (`sites_by_y[1 - Y]`); getting it wrong swaps
     pad pairs (see "Pitfalls").
   - *route-config*: HROW `*_ACTIVE`, REBUF `GCLKn_ENABLE_ABOVE/BELOW`,
     HCLK_CMT `*_USED`, HCLK `ENABLE_BUFFER.*`; owned by the net that uses
     the named wire (for REBUF: the GCLK line through the tile, either half).
   - BRAM tile features with no site, and `RAMB36.*`: the tile pseudo-cell.
   - anything else: `unassigned` with a reason (none in these images).
2. **Nodes** (`xc7graph.Fabric.node`): the wires joined by `tileconn.json`,
   found lazily by BFS in both directions and memoised. This is the same
   union as prjxray `NodeModel`, without building all ~20 M wires.
3. **Roots** (`Builder.resolve`): walk each node back through its active
   driver: a FASM pip into one of its wires, or an `always` ppip. A node that
   contains a site output pin is a root (the net driver). When nothing drives
   it, a `default` ppip makes it `$VCC_DEFAULT`; otherwise it is undriven.
   Bidirectional pips are tried in both directions; with several candidate
   drivers, FASM pips win, then drivers that reach a pin of a site that has
   configuration. A net = everything with the same root.
4. **Ownership of pips**: every FASM pip line goes to the net of the root of
   its driving end (so stubs and antennas are kept, owned by the net that
   feeds them).
5. **Cell pins**: for every input pin of every cell, its root net (sink);
   every output pin that is a root is the driver. A site without FASM lines
   becomes an *implicit* cell only when it drives a routed net (here: 4 GTP
   input pads `IPAD_*`). Sinks fed only through a dedicated wire (carry chain
   `COUT -> CIN`, BRAM cascade, OLOGIC/ILOGIC shift and feedback wires) from
   a site with no configuration are not connected (760 pins, listed in
   `notes`).

## Logical view (`xc7bels.py`)

Decodes cells into primitives with the prjxray feature semantics (the same
rules as fasm2bels `clb_models.py`, `ioi_models.py`, `iob_models.py`):

- SLICE: `LUT6` / `LUT5` / `LUT6_2` (with the truth table reduced to its
  support after folding inputs tied to VCC/GND), `FDRE/FDSE/FDCE/FDPE/LDCE/LDPE`
  (from `FFSYNC`, `LATCH`, `xFF.ZRST`; `INIT = !ZINI`), `CARRY4`, `MUXF7`,
  `MUXF8`, `SRLC32E/SRL16E/RAM64X1S/RAM32X1S` (SLICEM modes, generic ports).
  Every SLICE feature must be consumed by the decoder: **unconsumed features:
  none**. Note `PRECYINIT.C0` and `NOCLKINV` have no set bits but are
  emitted for nearly every slice; they do not imply a used carry.
- IOB -> `IBUF` / `OBUF` / `OBUFT` / `IOBUF` (`IOB_CFG_ONLY` for pads with
  configuration and no load), using the OLOGIC tristate path: OLOGIC with
  `OMUX.D1` + `DATA_RATE_TQ.BUF` is a bypass, `TQ = ZINV_T1 ? T1 : ~T1`; an
  unrouted T1 is the IMUX default VCC, so no `ZINV_T1` + unrouted T1 means
  an always-enabled output.
- ILOGIC without ISERDES/IDDR: bypass `O = D` (both the placed form with
  `ZINV_D` and the route-through form of an unused site; **I**: the
  route-through has no inverter).
- RAMB18 halves stay `RAMB18E1` (SDP or TDP from the features); hard blocks
  (`PCIE_2_1`, `GTPE2_*`, `MMCME2_ADV`, `BUFGCTRL`, `BUFHCE`, `IBUFDS_GTE2`)
  are site-level primitives with site pin names as ports and the raw
  features as parameters.

Result for the flash update image: 47,491 primitives (LUT6 19,481,
LUT6_2 5,756, FDCE 18,647, FDPE 1,710, FDRE 1,168, FDSE 40, CARRY4 270,
MUXF7 16, SRLC32E 7, SRL16E 4, RAMB18E1 48, IOBUF 65, IBUF 72, OBUF 67,
BUFGCTRL 5, BUFHCE 11, MMCME2_ADV 1, PCIE_2_1 1, GTPE2_CHANNEL 1,
GTPE2_COMMON 1, ...), 55,528 logical nets, 2 without driver (VCC/GND
pseudo-nets), no net with more than one driver. These counts agree with
the layer-3 feature heuristics (about 25.1k LUTs, 21.6k FFs, 270 carry
slices, 15 SRL/LUTRAM, 48 RAMB18).

`xc7bels.py verilog` writes `work/l4/update.v`: one `module i2cfpga` with
the pads as ports, UNISIM-like instances, LUT equations as comments.

## Pitfalls found on the way (and fixed)

- **IOB/IOI site naming.** prjxray's `IOB_Y0` is the *upper* site of a
  LIOB33/RIOB33 tile (even global Y), not the site with relative y 0. With
  the naive mapping every pad pair's features land on the wrong pad, which
  looked like 19 never-driven I2C pads and 8 open-drain pads with inverted
  tristate. With the fasm2bels rule the IO ring becomes uniform: 64
  open-drain IOBUF (T from FDPE INIT=1), 64 LUT-driven OBUF, 72 IBUF.
  The FASM partition was lossless either way; only the meaning changed.
- **LUT6_2 with A6 = VCC.** The O6 function of a fractured LUT is the upper
  half of INIT; taking the support over all 64 bits gave false
  dependencies and even a false combinational loop. Constant inputs are now
  folded before the support is taken.
- **Zero-bit features.** `PRECYINIT.C0`, `NOCLKINV` and `RAMB36.*`
  defaults appear in the FASM although they set no bits.

## Limitations

- The netlist is only as good as prjxray-db: pips without segbits and
  without a ppip entry (`unknown`: some IOI clock pips, PCIE_INT_INTERFACE
  IMUX delay bypasses, CMT/HCLK_CMT pips, the ILOGIC `D->>O`
  route-through) are never followed. Pins that could only be driven that
  way are listed per cell in `unknown_pins`.
- The 3 CFG_CENTER bits and the GTP ECC overrides stay in layer 3's
  unknown-bits file; they are not part of the FASM and so not of the
  netlist.
- Logical primitives for SLICEM RAM/SRL modes use generic ports (A1..A6,
  D, WE, CLK) rather than exact UNISIM port lists.
- BRAM halves are kept as two RAMB18E1; merging into RAMB36E1 (as
  fasm2bels does when both halves share addresses) is not attempted.
- The Verilog is a readable view, not a simulation or resynthesis model.
