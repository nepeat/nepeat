How frames are observed: a frame sent out netdev X leaves port X and enters the ASIC on the
other port. A routed copy leaving on port P re-enters on the far port with the next hop's DMAC
(not a router MAC) and is flooded in that port RIF's internal VLAN to the CPU, so it shows up on
the far port's netdev; frames the ASIC sends to the CPU show up on the netdev of the port they
entered. tools/l3_frames.c tags its frames and groups what comes back by (netdev, DMAC, SMAC,
TTL, length). RIF A = Ethernet0 (MAC ..01:0a), RIF B = Ethernet120 (..01:0b), H1 = ..0a:02
(neighbor on A), H2 = ..0b:02 (neighbor on B). "in A" = sent on Ethernet120 (enters RIF A).

What isai does differently (oracle l3-basic 050141, l3-ecmpw 052440; names from each pyctypes)
  - port RIF: intf TYPE L3PORT on the sysport, sysport PORT_FWD_MODE 1 (no VLAN); ours: SVI on the
    frontend's internal VLAN (works, see above; unknown unicast entering a routed port floods to the CPU)
  - L3VNI attrs IPV4/IPV6_UNICAST_TTL_CHECK_FAIL_CTC, IPV4_OPTIONS_CTC + _DROP at creation; node
    TTL_CHECK_PROFILE_1_THRESHOLD 0; IP2ME routes TTL_CHECK_PROFILE 1  (ours now: the TTL ones)
  - ECMP weight = repeated nexthop, ifcs_ecmp_member_replace for every change  (ours now: same)
  - glean (connected subnet) routes copy to their own hostif trap, IP2ME to another (ours: one shared)
  - RIF counters: node INGRESS/EGRESS_L3INTF_STATS_MODE/_CONFIG before node enable, then
    ifcs_intf_stats_get (ours: backend ready, needs a frontend hook and the node config, see sai-features.md)
  - default VR = L3VNI 0 (ours L3VNI 1)

Found, not L3: ifcs_l2vni_delete of a port RIF's internal VLAN returns BUSY in every run (traces
050006, 050107, 051901); the frontend ignores it, and the next port RIF on that port fails
ITEM_ALREADY_EXISTS (l3-ns 051901 step 0.47). isai flushes the L2VNI's entries
(ifcs_l2_entry_delete_all) before deleting an L2VNI.
