== State found (cold boot on slot A = #uboot-cs8210-stage3app e5723798, i.e. selfinit ac03324c)
MDIO FPGA 0004:01:00.0: "[Firmware Bug]: BAR 0: invalid; can't size" (and BAR 1), Mem-; Credo libMdio "resource0 not available"
Its config space: BAR0 e0200000, BAR1 00200000. From Linux (decode off): writing BAR0 =
  e0000000 -> e0000000, e0300000 -> e0200000, 0 -> 0, fff00000 -> e0200000, ffffffff -> e0200000.
=> BAR 0 keeps only bits 31:29 and 21 (read = written & 0xe0200000) and comes out of reset as e0200000. That value
   equals its own sizing read-back, which Linux's pci_size() rejects ("can't size"). The vendor U-Boot writes
   e0000000 first (vendor prompt: 03.00.00 BAR0 e0000000, BAR1 00200000, COMMAND 0), so Linux sizes it from there.
   Our U-Boot left the partners alone (endpoint nodes disabled), so the reset value reached Linux.
