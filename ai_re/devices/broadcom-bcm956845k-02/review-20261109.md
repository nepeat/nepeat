## Findings to act on

1. **Evidence gap on measured offsets.** `sdk-netdev/README.md` says the
   `bcm_pkt_t` offsets (`0x44` length, `0x85` src port, `0x87` flags, `0xa4`
   rx flags, `0x48`/`0x54` tx bitmaps) and the L2 layout were "measured through
   CINT", but `sdk-session-20261109.txt` does not contain those measurements.
   I verified the L2 struct from the binary; the packet offsets remain
   unverified by anyone but the original session. Capture the CINT
   `sizeof`/offset output into this subdir so the adapter's memory safety rests
   on recorded numbers.
2. **`950-bcm-sdk-tap-bridge-domain.patch` (in progress) — notes:**
   - Mechanism is right: `ndo_get_port_parent_id` puts all `swpN` in one
     bridge hwdom, `offload_fwd_mark=1` on TAP-ingress frames stops the bridge
     re-flooding to sibling swp ports, `CHANGEUPPER` error returns are honored
     by `__netdev_upper_dev_link`, and both `switchdev_bridge_port_*` signatures
     match 6.12. `CONFIG_NET_SWITCHDEV=y`, `CONFIG_BRIDGE=y`, `CONFIG_TUN=m`
     confirmed in `artifacts/kernel.config`.
   - The patch exists in `overlay/` but the build tree has it only hand-applied
     in `build_dir` (`tun.c` has 4 hits; `work/source/.../patches-6.12/` has no
     950). Run the next build through `prepare.py` so quilt application is
     exercised before any evidence is recorded against it.
   - Invariant worth writing down in `offload/README.md`: the mark is correct
     only if every frame the ASIC copies to the CPU was also forwarded/flooded
     by the ASIC. A *trapped* frame (CPU-destined static L2 hit, or any future
     "do not flood unknown unicast" policy) marked this way will not be
     software-forwarded either.
   - No `NETDEV_UNREGISTER` handling while offloaded; the `!linking` branch
     covers normal bridge removal. Indentation is spaces, kernel style is tabs.
   - Gating by module parameter plus the `swp%u` name is fine for the
     prototype; a per-device flag would be cleaner later.
3. **Apply path bounces every front-panel port.** `bcm-switch apply` issues
   `port xe enable=false` before rebuilding VLANs on *every* UCI reload, and the
   TAP admin-sync then flaps `IFF_UP` on all `swpN`, which netifd sees as link
   events. Acceptable for bring-up; flag for an incremental apply. Related:
   there are two authorities for port admin state (UCI `enabled` vs `ip link`).
   `offload/README.md` names the problem; `asic-integration.md` should state the
   rule (e.g. "UCI wins at apply time, Linux wins between applies").
4. **Validation nits in `bcm-switch`:** `read_port` defaults `speed` to `10000`
   while the shipped config and LuCI use `0`; `read_port`/`read_vlan` overwrite
   `$bad`, so only the *last* validation error is reported.
5. **Evidence files are overwritten on re-run.** Both hardware tests write to
   fixed `…-20261109.json` names that the READMEs link to as proof. Write to a
   timestamped name, or refuse to overwrite an existing record.
6. **Build input not documented.** `prepare_sdk.py` requires
   `firmware/linux-rootfs.bin`, which is gitignored. `openwrt/README.md` should
   say so and point at `firmware-dump.md` + `extract_fat16.py` for regeneration.
7. **`PROGRESS.md` shape.** 250 lines; "current state" is scattered across
   dated entries. Per `CLAUDE.md`, add a short **Current status** block under
   the H1 (device state, tmux session, booted image hash, what is RAM-only),
   then keep the dated entries below it.
8. **Nothing is committed.** The stageable set is clean (1.6 MiB after the
   ignore fix above). Commits are being made from the session history in
   small work units; in-flight files are left for the native-integration
   change to land.
9. **Flake evaluation fails on a dirty tree.** `flake.nix` embeds
   `${./tools/lab_power.py}`, and Nix refuses untracked paths, so `use flake`
   (direnv) and plain `nix develop` both failed until the file was in the
   index. Fixed with `git add -N tools/lab_power.py` (intent-to-add; reverse
   with `git reset`). Prefer that over the README's `nix develop path:.`: the
   `path:` fetcher copies the whole directory into `/nix/store`, including the
   3.4 GiB `openwrt/work/` tree. Once `tools/` is committed this goes away.
10. Aside, different project: a `git log -G 'eyJhbGciOi'` sweep hit
   `aislop/devicehunt/.../*.html.headers` in `d072711` (JWT-looking strings
   inside captured HTTP response headers). Likely a site's own token; worth a
