# switch/sonic: SONiC's control plane as NixOS services

`services.sonic` runs redis, syncd (virtual SAI or a vendor libsai),
orchagent and the managers/syncers for ports, VLANs and PortChannels, with
CONFIG_DB owned as in the sonic-nixos device notes (`config-ownership.md`):
NixOS enforces or seeds what Nix declares, `config`/`config save` own the
rest. Packages: [../../../packages/sonic](../../../packages/sonic/default.nix)
(`sonic.python`: sonic-py-common, sonic-cfggen, YANG models + validator,
sonic-utilities).

## units

```
redis-sonic ─ sonic-config-loader (oneshot: Nix base + saved file -> CONFIG_DB)
              ├ sonic-nix-apply (oneshot, restarted by nixos-rebuild when the base changes)
              ├ sonic-nix-watch (flags runtime changes to enforced keys)
              └ sonic-syncd ─┬ sonic-portsyncd
                             └ sonic-orchagent ─ portmgrd intfmgrd vlanmgrd nbrmgrd teammgrd
                                                 teamsyncd tlm_teamd neighsyncd fdbsyncd coppmgrd
```

All are `sonic-*.service`, `PartOf=sonic.target`. A downstream unit
`BindsTo` its upstream and the upstream `Upholds` it, so a syncd or
orchagent crash restarts everything below it (SONiC restarts the swss/teamd
containers with syncd). Consequence: `systemctl stop sonic-orchagent` is
undone by syncd; stop `sonic.target` instead. The loader is not restarted by
`systemctl restart sonic.target` or `nixos-rebuild switch` (unsaved runtime
config survives both).

## ownership

| rule | where |
| --- | --- |
| host tables (MGMT_*, NTP*, SYSLOG*, AAA, ...; option `hostTables`) and DEVICE_METADATA hostname | dropped from the saved file, flagged when written at runtime |
| enforce: DEVICE_METADATA platform/hwsku/mac, PORT lanes/alias/index, breakout speeds, `settings` by default | Nix value at boot and rebuild; a runtime/saved difference is logged and shown |
| seed: other PORT fields (speed of unsplit cages, admin_status = down, mtu = 9100, `settings.PORT.*`) | Nix value only where the user has none; rebuild writes a changed seed only over the old Nix value |
| unmanaged: everything else | `config ...` + `config save` |

Modes: `fieldModes` > `keyModes` > hardware rules > `tableModes` > PORT seed /
`defaultMode`. Key parts that are front-panel aliases are translated
(`settings.VLAN_MEMBER."Vlan100|Ethernet3/1"`); values are not. PORT entries
not generated by Nix (e.g. after a breakout change) are dropped together with
entries keyed by them.

Conflicts go to `/run/sonic-nix/conflicts.json`, `/etc/issue.d/sonic-nix.issue`
(-> `/run/sonic-nix/issue`; agetty is asked to redraw) and the SSH motd
(`users.motdFile` = `/run/sonic-nix/motd`). `sonic-nix-diff` (`--json`,
`--all`) lists them plus seeded fields the user changed; exit 1 while
conflicts are pending.

## ports

`cages` = lanes per front-panel cage (`port-maps/accton-as7712-32x.nix`, the
public AS7712 32x100G map, same as the AS7760 factory one). Every cage is one
`defaultSpeed` port unless `breakout."<cage>"` lists every resulting port:

```nix
services.sonic.breakout."1" = [
  { alias = "Ethernet1/1"; lanes = [ 49 ]; speed = 25000; }
  { alias = "Ethernet1/2"; lanes = [ 50 ]; speed = 25000; }
  { alias = "Ethernet1/3"; lanes = [ 51 ]; speed = 25000; }
  { alias = "Ethernet1/4"; lanes = [ 52 ]; speed = 25000; }
];
```

SONiC name = `Ethernet<4*(cage-1)+sub-1>` (a 2x50G cage 1 gives Ethernet0 and
Ethernet1, not SONiC's usual Ethernet0/Ethernet2). Eval-time assertions: each
lane of the cage exactly once, no foreign lane, names `Ethernet<cage>/<1..4>`
and unique, speed valid for the lane count (`validSpeeds`), cage exists,
`settings.PORT` keys exist. The Nix base is YANG-validated at build time
(`system.build.sonic.base`); the merged config again at boot (warning only).
A breakout change on `nixos-rebuild switch` is not applied live:
`sonic-nix reload` (restarts the stack).

## files

`/var/lib/sonic/config_db.json` (`config save`), `/usr/share/sonic` ->
generated device/hwsku tree (port_config.ini, sai.profile, lanemap.ini),
`/run/redis/sonic-db/database_config.json` (no chassis instance; redis has
20 databases), `/etc/sonic/{sonic_version.yml,copp_cfg.json}`, `/zmq_swss`
(orchagent's ZMQ endpoints). CLI: `SONIC_CLI_IFACE_MODE=alias` for login
shells and kept by sudo; `config reload` calls `sonic-nix reload`.

## hardware

Kernel: `BRIDGE` + `BRIDGE_VLAN_FILTERING` (vlanmgrd), `VLAN_8021Q`,
`NET_TEAM` + `NET_TEAM_MODE_LOADBALANCE` (teamd), `DUMMY`; `TUN` for the
virtual SAI (`kernelModules` loads them). Vendor SAI: `sai.kind = "vendor"`,
`sai.package = sonic.sairedis-openbcm libsai`, `sai.libraryPath`,
`sai.initConfigFile`, `sai.profile`. syncd `Conflicts=` the units in
`sai.conflicts` (default: openbcm-asic-temp when enabled; one SDK process
per unit) and starts after them; start openbcm-asic-temp again by hand
after stopping the stack.

## not here (yet)

buffermgrd/buffer profiles, vrfmgrd, vxlan/nat/sflow/macsec managers,
fpmsyncd/FRR, swssconfig's switch.json, LLDP, warm reboot, multi-ASIC,
config.bcm generation for breakouts (`sai.initConfigFile` points at an SDK
config kept outside the store).
