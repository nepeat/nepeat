# switch/sonic: SONiC's control plane as NixOS services

`services.sonic` runs redis, syncd (virtual SAI or a vendor libsai),
orchagent and the managers/syncers for ports, VLANs and PortChannels, with
CONFIG_DB owned as in the sonic-nixos device notes (`config-ownership.md`):
NixOS enforces or seeds what Nix declares, `config`/`config save` own the
rest. Packages: [../../../packages/sonic](../../../packages/sonic/default.nix)
(`sonic.python`: sonic-py-common, sonic-cfggen, YANG models + validator,
sonic-utilities).

## units

```
redis-sonic ─ sonic-config-loader (oneshot: Nix base + saved file -> CONFIG_DB)
              ├ sonic-nix-apply (oneshot, restarted by nixos-rebuild when the base changes)
              ├ sonic-nix-watch (flags runtime changes to enforced keys)
              └ sonic-syncd ─┬ sonic-portsyncd
                             └ sonic-orchagent ─ portmgrd intfmgrd vlanmgrd nbrmgrd teammgrd
                                                 teamsyncd tlm_teamd neighsyncd fdbsyncd coppmgrd
                                                 vrfmgrd (vrf.nix)
                                                 teamd-watch (recovery.nix, upheld by teammgrd)
                                                 frr-config ─ frr-mgmtd ─ frr-zebra ─┬ frr-staticd ┬ bgpcfgd ─ staticroutebfd
                                                 fpmsyncd  (frr.nix)                 ├ frr-bgpd ───┼ bgpmon
                                                                                     └ frr-bfdd ───┴ bfdsyncd   (bfd.nix)
```

All are `sonic-*.service`, `PartOf=sonic.target`. A downstream unit
`BindsTo` its upstream and the upstream `Upholds` it, so a syncd or
orchagent crash restarts everything below it (SONiC restarts the swss/teamd
containers with syncd). syncd is also `PartOf` orchagent ([recovery.nix](recovery.nix)):
a requested stop or restart of orchagent (e.g. `nixos-rebuild switch` with a
changed orchagent unit) takes syncd along, since orchagent against a running
syncd left no KNET netdevs. Stop `sonic.target` to stop the stack. The loader is not restarted by
`systemctl restart sonic.target` or `nixos-rebuild switch` (unsaved runtime
config survives both).

Crash recovery ([recovery.nix](recovery.nix)): every syncd start is a cold
start as in swss.sh (APPL/ASIC/COUNTERS/FLEX_COUNTER/APPL_STATE DBs flushed,
stale STATE_DB tables removed); an orchagent *failure* (crash, kill, abort;
not a requested stop) restarts syncd and so everything below it, as SONiC
restarts swss with syncd (orchagent alone left the KNET netdevs gone). A dead
teamd is respawned by `sonic-teamd-watch` with its old arguments plus `-o`
(take over the team netdev: IP, VLANs and members stay, other PortChannels
untouched; tlm_teamd reconnects; the netdev MAC, which `-o` resets to the system
MAC, is put back for a PORTCHANNEL_INTERFACE `mac_addr`); after 3 failed tries
teammgrd restarts. With systemd-networkd the module turns off its
ManageForeignRoutingPolicyRules/Routes: a networkd restart deleted vrfmgrd's
local rule (pref 1001) and so every local delivery, SSH included (CS8210).

## ownership

| rule | where |
| --- | --- |
| host tables (MGMT_*, NTP*, SYSLOG*, AAA, ...; option `hostTables`, fields: `hostFields`) | dropped from the saved file, flagged when written at runtime |
| enforce: DEVICE_METADATA platform/hwsku/mac + hostname/timezone (mirrored from `networking.hostName`/`time.timeZone`), PORT lanes/alias/index, breakout speeds, `settings` by default | Nix value at boot and rebuild; a runtime/saved difference is logged and shown |
| seed: other PORT fields (speed of unsplit cages, admin_status = down, mtu = 9100, `settings.PORT.*`) | Nix value only where the user has none; rebuild writes a changed seed only over the old Nix value |
| unmanaged: everything else | `config ...` + `config save` |

Modes: `fieldModes` > `keyModes` > hardware rules > `tableModes` > PORT seed /
`defaultMode`. Key parts that are front-panel aliases are translated
(`settings.VLAN_MEMBER."Vlan100|Ethernet3/1"`); values are not. PORT entries
not generated by Nix (e.g. after a breakout change) are dropped together with
entries keyed by them.

Conflicts go to `/run/sonic-nix/conflicts.json`, `/etc/issue.d/sonic-nix.issue`
(-> `/run/sonic-nix/issue`; agetty is asked to redraw) and the SSH motd
(`users.motdFile` = `/run/sonic-nix/motd`). `sonic-nix-diff` (`--json`,
`--all`) lists them plus seeded fields the user changed; exit 1 while
conflicts are pending.

## ports

`cages` = lanes per front-panel cage (`port-maps/accton-as7712-32x.nix`, the
public AS7712 32x100G map, same as the AS7760 factory one). Every cage is one
`defaultSpeed` port unless `breakout."<cage>"` lists every resulting port:

```nix
services.sonic.breakout."1" = [
  { alias = "Ethernet1/1"; lanes = [ 49 ]; speed = 25000; }
  { alias = "Ethernet1/2"; lanes = [ 50 ]; speed = 25000; }
  { alias = "Ethernet1/3"; lanes = [ 51 ]; speed = 25000; }
  { alias = "Ethernet1/4"; lanes = [ 52 ]; speed = 25000; }
];
```

SONiC name from the first lane, as SONiC does: `Ethernet<stride*(cage-1) + index of
the first lane in the cage>`, stride = lanes of the widest cage (QSFP28 4, QSFP-DD 8;
2x50G cage 1 of 4 lanes: Ethernet0, Ethernet2). Eval-time
assertions: each lane of the cage exactly once (`allowUnusedLanes`: the upper lanes may stay
unused, e.g. Teralynx 1x100G on 8 lanes), subports in lane order, no foreign lane, names `Ethernet<cage>/<1..stride>`
and unique, speed valid for the lane count (`validSpeeds`), cage exists,
`settings.PORT` keys exist. The Nix base is YANG-validated at build time
(`system.build.sonic.base`); the merged config again at boot (warning only).
A breakout change on `nixos-rebuild switch` is not applied live:
`sonic-nix reload` (restarts the stack).

Vendor SDK config: a board sets `sai.sdkConfig.generator`, a function
`{ ports, settings } -> file` called with these ports (name, alias, lanes,
speed) and `sai.sdkConfig.settings` (global SDK keys; `null` removes one).
Its file (`system.build.sonic.sdkConfig`) is the default
`sai.initConfigFile`, so the SDK always initialises the ports SONiC has; the
generator's build must fail unless the config's ports equal the given ones.
Setting `sai.initConfigFile` to a path still works. The module itself knows
no chip: the AS7760 board uses
[packages/openbcm/configs](../../../packages/openbcm/README.md#configs) (Tomahawk).

## VRFs and counters

`vrf.enable` (default on, [vrf.nix](vrf.nix)): vrfmgrd + the kernel's `vrf`
module; `config vrf add Vrf-x`, `config interface vrf bind <port> Vrf-x`.
At start vrfmgrd removes VRF devices it did not create and moves the `local`
ip rule from pref 0 to 1001, as on SONiC. `flexCounters`
([counters.nix](counters.nix)): FLEX_COUNTER_TABLE groups seeded into
CONFIG_DB (default: PORT only; sai-openbcm also answers ACL counters, which
`counterpoll acl enable` turns on), so syncd polls port stats from boot;
`counterpoll` + `config save` override them.

## hardware

Runs on the AS7760 at boot (wiring: [boards/as7760](../../boards/as7760/default.nix);
results: devices/sonic-nixos/PROGRESS.md) and on the AS7772 ([boards/as7772](../../boards/as7772/default.nix):
the same board with MACsec PHYs in front of every port, brought up by `hardware.openbcm.mdioScript` before syncd
and described to the SAI by its `SAI_OPENBCM_PORT_*` keys; devices/edge-core-as7772-32x/sonic.md). Kernel: `NET_VRF` (vrfmgrd; module `vrf`, loaded by vrf.nix), `BRIDGE` + `BRIDGE_VLAN_FILTERING` (vlanmgrd), `VLAN_8021Q`,
`NET_TEAM` + `NET_TEAM_MODE_LOADBALANCE` (teamd), `DUMMY`; `TUN` for the
virtual SAI (`kernelModules` loads them). Vendor SAI: `sai.kind = "vendor"`,
`sai.package = sonic.sairedis-openbcm libsai`, `sai.libraryPath` (boards/as7760: libsai is
`hardware.openbcm.package`, the Rust SAI of rust/sai (`hardware.openbcm.rustSai`; the C++ sai-openbcm
was deleted on 2026-11-23), its tools and boot-time MDIO tool included),
`sai.sdkConfig` / `sai.initConfigFile`, `sai.profile`. syncd `Conflicts=` the units in
`sai.conflicts` (default: openbcm-asic-temp when enabled; one SDK process
per unit) and starts after them. `sai.restartOnStop` units are started
again 10 s after syncd stops, unless syncd is back, queued or a
`sonic-nix reload` runs.

## routing (FRR)

[frr.nix](frr.nix), `services.sonic.frr.enable` (default on, as SONiC's bgp
feature): FRR 10.7 (zebra, mgmtd, bgpd, staticd, bfdd: see BFD below; [packages/sonic/routing](../../../packages/sonic/routing/default.nix)
with the SONiC patches the FPM path needs, linked against a json-c with the
upstream json_object_put() leak fixes: see devices/sonic-nixos/bfdd-leak.md), zebra `-M dplane_fpm_nl` to
fpmsyncd (127.0.0.1:2620 -> APPL_DB ROUTE_TABLE), bgpcfgd + bgpmon. SONiC's
default "separated" mode: `/etc/frr/{zebra,bgpd,staticd}.conf` rendered from
CONFIG_DB by `sonic-frr-config` at every start (docker-fpm-frr's templates,
`/etc/sonic/constants.yml`), then bgpcfgd applies CONFIG_DB changes
(BGP_NEIGHBOR, STATIC_ROUTE via `config route add`, ...) live through
vtysh; never a Nix or hand-edited FRR file. Unified/frrcfgd mode is not
built (a warning when CONFIG_DB asks for it). vtysh is on PATH (`show ip
route`, `show ip bgp summary`, `config interface ip remove`).
bgpcfgd configures no BGP_NEIGHBOR until these exist: `DEVICE_METADATA`
`bgp_asn` (e.g. `settings.DEVICE_METADATA.localhost.bgp_asn`), `type` and
`BGP_DEVICE_GLOBAL|STATE` (both seeded: LeafRouter, SONiC's init_cfg
values) and **Loopback0** (`config loopback add Loopback0`). `FEATURE|bgp`
is seeded enabled (init_cfg.json), so coppmgrd installs the bgp/bgpv6 CoPP
traps (sai-openbcm polices them as BGP, not as generic IP2ME). bgp_asn and
Loopback0 are read into bgpd.conf at FRR start (`systemctl restart
sonic-frr-config` after changing them). BGP_NEIGHBOR `local_asn` (+ `local_as_no_prepend`,
`local_as_replace_as`, the YANG fields) -> `neighbor <ip> local-as N [no-prepend [replace-as]]`, at
creation and live (packages/sonic/routing patches 0004/0005; upstream bgpcfgd ignores them). Firewall: `frr.openFirewall` (default
on) accepts TCP 179 on every interface except `frr.managementInterfaces`
(`eth0`); without it the NixOS firewall drops BGP and sessions stay in Connect.

## BFD (software)

[bfd.nix](bfd.nix), `services.sonic.bfd.enable` (default on with FRR): FRR's
bfdd, no ASIC offload (Tomahawk BFD needs closed microcontroller firmware;
sai-openbcm has no SAI BFD; the vs SAI gets `SAI_VS_BFD_OFFLOAD_SUPPORTED=false`).
Both ways in are CONFIG_DB:

- BGP: `BGP_NEIGHBOR|[<vrf>|]<ip>` `bfd=true` (+ `bfd_check_ctrl_plane_failure`,
  fields of sonic-bgp-common.yang) -> `neighbor <ip> bfd` (template patch 0002;
  bgpcfgd ignores these upstream; a change on a live neighbor is applied,
  patch 0003). bgpd runs its own bfdd session, FRR defaults 300 ms x3, and
  drops the session on BFD down.
- Static routes: `STATIC_ROUTE|<vrf>|<prefix>` with `nexthop`, `ifname` (the
  SONiC name of a port/PortChannel whose IP is in INTERFACE/PORTCHANNEL_INTERFACE)
  and `bfd=true` (one value per next hop). staticroutebfd -> APPL_DB
  BFD_SESSION_TABLE -> orchagent's BfdOrch (no offload: STATE_DB
  BFD_SOFTWARE_SESSION_TABLE) -> bgpcfgd's BfdMgr (`SYSTEM_DEFAULTS|software_bfd`
  enabled, seeded) -> bfdd; bfdsyncd -> STATE_DB BFD_SESSION_TABLE ->
  staticroutebfd puts the route in APPL_DB STATIC_ROUTE (-> staticd) while a
  next hop's session is Up. Timers: `bfd.staticRoute` (300 ms x3; SONiC 50 ms).
- `show bfd summary`, `show bfd peer <ip>` (STATE_DB), `vtysh -c 'show bfd peers'`.
- Firewall: UDP 3784/4784/3785 on all but `frr.managementInterfaces`, as BGP.

Not SONiC's: bfdsyncd (ours; SONiC has nothing that reports software
session state: polls bfdd's vty socket every `bfd.pollInterval`, 200 ms,
writes only BfdOrch's fields because orchagent's BfdMonitorOrch parses the
table), BfdMgr sessions active by default (upstream passive: two SONiC ends
never come up), no bfdmon (DPU-only). Limits: `config route add` has no
`bfd` option (write CONFIG_DB); staticroutebfd ignores VLAN interfaces
(upstream); a static BFD route and a BGP BFD neighbor on the same next hop
make two bfdd sessions to one peer (one with interface, one without), and
bfdd matches an unset local address or interface as a wildcard, so one can
capture the other's packets (seen in the VM on the peer side): use one or
the other per next hop. Each state change logs orchagent's harmless "BFD session for
<ip> not found" warning (BfdMonitorOrch is for VNET routes; same with SONiC's
hardware BFD). Details, numbers and the switch test:
devices/sonic-nixos/bfd.md.

## platform (pmon) and LLDP

`pmon.nix`: `services.sonic.pmon` runs xcvrd, thermalctld, psud, syseepromd
(`sonic-<daemon>.service`, PartOf sonic.target, not bound to syncd) over
`pmon.platformPackage`, a board's `sonic_platform` (API 2.0; AS7760:
[boards/as7760/sonic_platform](../../boards/as7760/sonic_platform/), notes in
devices/edge-core-7760-32x/sonic-platform.md), and installs the CLI scripts
(fanshow, tempershow, psushow, sfpshow, decode-syseeprom, sfputil). Fan
control is the board's: thermalctld runs a policy only if the chassis returns
a thermal manager, and no thermal_policy.json is installed.
`lldp.nix`: `services.sonic.lldp` runs lldpd (no SNMP, SONiC's patch 0001) on
`lldp.interfaces` (default `Ethernet[0-9]*`), its config rendered from
CONFIG_DB at start (docker-lldp's templates, `pause` dropped), lldpmgrd
(port ID = alias) and lldp_syncd (APPL_DB `LLDP_ENTRY_TABLE`); seeds
`FEATURE|lldp` enabled (coppmgrd's LLDP trap, lldpshow). `show lldp
neighbors|table` call lldpctl directly. Packages: [packages/sonic/platform](../../../packages/sonic/platform/default.nix).
`sflow.nix`: `services.sonic.sflow` runs sflowmgrd (bound to orchagent; its `service hsflowd restart|stop` goes
through a shim to sonic-hsflowd.service), hsflowd 2.1.26 (FEATURES=SONIC: mod_sonic, mod_psample, mod_dropmon; conf
`sonic { waitReady=10 }`: no sysmonitor sets SYSTEM_READY) and port_index_mapper; seeds `FEATURE|sflow` enabled
(coppmgrd's SAMPLEPACKET trap + genetlink hostif psample). Samples come from the platform SAI through the kernel's
psample group 1. Packages: [packages/sonic/sflow](../../../packages/sonic/sflow/default.nix) (also sflowtool).

## MACsec

[macsec.nix](macsec.nix), `services.sonic.macsec` (default off): macsecmgrd (bound to orchagent) starts one
`wpa_supplicant -D macsec_sonic` per port with a profile (sonic-wpa-supplicant, [packages/sonic/wpa-supplicant](../../../packages/sonic/wpa-supplicant/default.nix):
MKA only, no Wi-Fi/EAP); the driver writes APPL_DB MACSEC_* tables, orchagent's MACsecOrch creates the SAI MACsec
objects. Needs a SAI with `sai_macsec_api_t` (ours: an external MACsec table, rust/sai `sai-macsec`; first board: AS7772).
```nix
services.sonic.macsec = {
  enable = true;
  profiles.lab = { cakFile = "/var/lib/sonic-macsec/lab.cak"; ckn = "<hex>"; };   # cipherSuite default GCM-AES-XPN-256
  ports."Ethernet1/1" = "lab";
};
```
- **The CAK never enters the store:** `cakFile` (one line of hex, 0600; a store path is an assertion failure) is read
  by `sonic-macsec-config` at every stack start and written to CONFIG_DB `MACSEC_PROFILE` in SONiC's "type 7"
  encoding together with `PORT.macsec`. Profiles and ports it wrote and that are no longer declared are removed;
  `config macsec` entries are left alone. A missing or malformed key file: that profile is not written, its ports get no
  MACsec (they run in clear) and the unit fails.
- Options per profile: `cipherSuite` (XPN-256 default: a 32-bit PN lasts 29 s at 100G), `priority`, `policy`,
  `rekeyPeriod`, `replayProtect` / `replayWindow`.
- macsecmgrd's compiled-in `/sbin/wpa_supplicant`, `/sbin/wpa_cli`, `/etc/wpa_supplicant.conf` are bound into its mount
  namespace. Stop is `KillMode=mixed`: macsecmgrd ends its sessions itself (its `wpa_cli` calls need the supplicants
  alive; with everything signalled at once a stop took 15 s and more).
- **An MKA session runs with the address its port has.** wpa_supplicant takes the netdev's MAC once, at start (SCI, key
  server election). macsecmgrd (swss patch 0003) starts a port's session only when the netdev has the port's
  `INTERFACE mac_addr`, if one is set (intfmgrd applies it after the port is ready), and starts it again within a second
  when the address changes (`ip link set address`, a `mac_addr` change); other ports are not touched. No unit-level
  wait: at a stack restart the old syncd's netdevs still exist, with the right address, until the new syncd replaces them.
- `show macsec` / `sonic-clear macsec`: docker-macsec's CLI plug-ins through wrappers in front of sonic-utilities'
  commands. **`show macsec` prints SAKs.** `FEATURE|macsec` is seeded enabled (coppmgrd's EAPOL trap).
- VM test: [tests/vm-macsec.nix](tests/vm-macsec.nix) (virtual SAI, two ports of one switch on one segment, one with a
  `mac_addr`): MKA up by itself at boot and after a syncd restart, sessions follow address changes. swss unit tests:
  `tests/mock_tests/macsecmgrd` (in the patch).
- Not here: fallback CAK, FIPS POST. Between a port coming up and its MKA session creating the MACsec port the port
  passes frames in clear (upstream SONiC behaviour; measured on the AS7772, its `macsec.md`).
